# Results

## Summary
Tab 2 now follows the scientist's definitions. `code/analyze_rule_change_units.py` (v2) defines instruction = trials 0 to 4, early = trials 5 to 14 and late = the last 10 trials of every switch block, keys results by block context (aud / vis / both), and uses as primary test a per-unit Kruskal-Wallis across the three phases with a within-block trial-label-shuffle null (5,000 shuffles) plus one-sided Dunn-style post-hoc contrasts (instruction > early, instruction > late) on the same shuffles. Per the scientist's final direction, the definition of a rule-updating unit is descriptive: mean rate in instruction trials > early AND > late (`kw_is_instruction_higher`); every such unit is available in the viewer as the default set. Pooled over contexts, 3,532 of 6,685 units (52.8%) meet it in at least one window, which is close to the ~1/3-per-window chance level for a unit with no phase effect, so the tests are offered as optional stricter tiers: omnibus p < 0.05 and both post-hoc p < 0.05 (rate >= 0.1 Hz) gives 841 units (12.6%; baseline only 220, evoked only 520, both 101), 0.01 thresholds give 472. BH q-values (across units, and within each unit's 12-test family) are computed but, per the scientist, not used in any default flag. Per context: aud 661, vis 779. Leading structures: CP 26% (120/462), AUDd 19%, MOp 19%, SSs 18%, VISal 17%, PL 16%, SSp 16%, MOs 15%. The earlier early-vs-late chunk permutation is kept as a secondary screen; with instruction trials excluded from "early" it finds no BH-robust unit (255 candidates at p < 0.01), confirming that the switch-locked activity sits in the instruction trials, in line with AutoDiscovery experiment node_3_10 (210/4,788 mPFC+MOs units, 4.4%).

Calibration (all sessions, `checks.txt`): the KW flag fires for 1.2% of units on average (max 1.7%) when the three phases are relabelled to mid-block pseudo windows (instruction := 40 to 44, early := 45 to 54, late := 20 to 29), versus 4.9% for the real phases in the baseline window; the omnibus alone is anticonservative (12.7% pseudo) because trial shuffles ignore autocorrelation, which is why both post-hoc requirements are part of the flag. Chunk-permutation nulls: baseline 7.0% mean / 10.5% max, evoked 6.3% / 7.2%. 26/26 checks pass, including agreement of H and chi2 p with `scipy.stats.kruskal`.

The app was restructured: controls in a sidebar, plots column and brain column. Tab 2 (final, after the scientist's further requests): whole-session block timeline (context, instruction / early / late trials, per-block window means); one raster with all blocks stacked in session order, trials chronological, plain spike marks with translucent bands marking the instruction / early / late trials of each block (changed from phase-coloured spikes at the scientist's request), each block labelled with its rewarded context, with a PSTH of instruction vs early vs late (optionally split by context); block-start / block-end aligned means with the structure population band; for the selected unit, the permutation null recomputed live for the current analysis window and context (three histograms with the observed H and post-hoc rank differences, plus null mean / 95th / 99th percentiles and p-values) next to the stored statistics; and a region table with units recorded (all sorted units), QC-pass units, rule-updating units for the selection, units expected under the shuffle null (sum of per-unit null pass rates, e.g. MOs 405 observed vs 410 expected for the definition set in the baseline window) and mean instruction / early / late rates. Dots, list and table follow the selected statistics window. `check_app.py` passes 3/3 (tab 2: 4 plots, 1 widget, 27 stats rows, no output errors).
